# 每周 IDEA 兼容检测与自动升级 PR 计划

> 状态：已完成（2026-11-06；空跑与自动 PR 路径已端到端验证，不兼容 Issue 路径待首次真实不兼容时观察）

**目标：** 让"MypiPlugin 支持新版 IntelliJ IDEA"从被动等用户报障，变成每周自动发现 + 自动验证 + 自动开 PR 的流水线。保留 `untilBuild` 上限不动，用人机配合代替裸奔兼容。

**背景：** 0.2.2 因 `untilBuild = "262.*"` 被 IDEA 2026.3（build 263）拒绝加载，用户侧表现为"插件无法正常使用"。0.2.3 已修复并补上发版期 `verifyPlugin` 双端关卡，但**发现新版本仍需人工盯**：IDEA 每次大版本发布（2026.3 → 2027.1 → …）都会重新触发同样的窗口期。

**Architecture：** 新增一条独立定时工作流 `.github/workflows/compat-watch.yml`。它查询 JetBrains 官方发布 API → 与仓库当前兼容上限比对 → 有新版本则改配置跑 Plugin Verifier → 通过开 PR、失败开 Issue。与现有 `release.yml`（tag 触发、负责发版）职责分离，互不干扰。

**Tech Stack：** GitHub Actions（ubuntu-latest）、JetBrains Products Releases API、IntelliJ Platform Gradle Plugin 2.18.1 的 `verifyPlugin`、Gradle 9 / JDK 21。

## 决策与取舍

| 决策 | 结论 | 理由 |
|---|---|---|
| 是否删除 `untilBuild` 让插件永久前向兼容 | **不删** | 插件用了 39 处 Reworked Terminal 实验 API，删上限会把"装不上"变成"装上后点 Pi 崩"，故障更难排查 |
| 验证通过后是否自动发版（打 tag） | **不自动** | 发版需要人工确认 CHANGELOG 与用户可见变更；自动 PR 已把人工成本压到 review + 打 tag 两步 |
| 检测频率 | 每周一次（周一 10:00 北京时间）+ 手动 `workflow_dispatch` | JetBrains 正式版约每季度一版，每周足够；手动入口用于紧急检查 |
| 自动 PR 用什么 token | `GITHUB_TOKEN` | 无需额外 secret；已知限制：它创建的 PR **不会触发其他 workflow**，若将来要 PR 级 CI 再换 PAT |
| 兼容范围配置位置 | 抽到 `gradle.properties`（Task 1） | 工作流只需改属性行，不用正则改代码；同时消除版本号/构建号在 `build.gradle.kts` 内多处字面量的漂移风险 |

**已否决方案：** ①用 `pluginVerification.ides.recommended()` 自动覆盖所有推荐版本——它会拉到未发布的 EAP，依赖解析常失败；②把 `verifyPlugin` 加进每次 push 的 CI——Verifier 需下载约 2.2 GB IDE 数据，每次 push 跑不现实，故只在发版（release.yml）与每周检测时跑。

### Task 2: 新建每周兼容检测工作流

**Files:**
- Create: `.github/workflows/compat-watch.yml`

- [ ] **Step 1: 写工作流骨架（含公共前置步骤）**

```yaml
name: Weekly IDEA Compatibility Watch

on:
  schedule:
    - cron: '0 2 * * 1'   # UTC 周一 02:00 = 北京时间周一 10:00
  workflow_dispatch:

permissions:
  contents: write
  pull-requests: write
  issues: write

concurrency:
  group: compat-watch
  cancel-in-progress: false

jobs:
  watch:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-java@v4
        with:
          java-version: '21'
          distribution: 'temurin'

      - uses: gradle/actions/setup-gradle@v3
```

后续 Step 2–7 的 `run` 片段均追加在 `steps:` 下。

- [ ] **Step 2: 检测最新正式版并判断是否需要升级**

```yaml
  - name: Detect latest IDEA release
    id: detect
    run: |
      # JetBrains 官方发布元数据;build 形如 263.7307.200,首段即平台构建号
      META=$(curl -fsSL 'https://data.services.jetbrains.com/products/releases?code=IIU&latest=true&type=release')
      NEW_VERSION=$(echo "$META" | jq -r '.IIU[0].version')
      NEW_BUILD=$(echo "$META" | jq -r '.IIU[0].build')
      NEW_MAJOR=${NEW_BUILD%%.*}
      CURRENT_UNTIL=$(grep -E '^pluginUntilBuild=' gradle.properties | cut -d= -f2)
      CURRENT_MAJOR=${CURRENT_UNTIL%%.*}
      echo "new=$NEW_VERSION($NEW_MAJOR) current=$CURRENT_MAJOR"
      if [ "$NEW_MAJOR" -le "$CURRENT_MAJOR" ]; then
        echo "needs_bump=false" >> $GITHUB_OUTPUT
      else
        echo "needs_bump=true" >> $GITHUB_OUTPUT
        echo "version=$NEW_VERSION" >> $GITHUB_OUTPUT
        echo "major=$NEW_MAJOR" >> $GITHUB_OUTPUT
      fi
```

无新版本时直接结束，**属正常成功路径**，不发通知。

- [ ] **Step 3: 有新版本时改配置**

```yaml
  - name: Bump compatibility range
    if: steps.detect.outputs.needs_bump == 'true'
    env:
      NEW_MAJOR: ${{ steps.detect.outputs.major }}
      NEW_VERSION: ${{ steps.detect.outputs.version }}
    run: |
      ORIGINAL=$(grep -E '^verifierIdeVersions=' gradle.properties | cut -d= -f2)
      SINCE=$(grep -E '^platformVersion=' gradle.properties | cut -d= -f2)
      # until-build 前移到新大版本
      sed -i -E "s/^pluginUntilBuild=.*/pluginUntilBuild=${NEW_MAJOR}.*/" gradle.properties
      # Verifier 目标 = 最低支持版 + 最新版,保证首尾两端都被验证
      sed -i -E "s|^verifierIdeVersions=.*|verifierIdeVersions=${SINCE},${NEW_VERSION}|" gradle.properties
      git diff gradle.properties
```

- [ ] **Step 4: 跑 Verifier（带缓存，并区分"不兼容"与"环境失败"）**

```yaml
  - name: Verify against both IDEs
    id: verify
    if: steps.detect.outputs.needs_bump == 'true'
    continue-on-error: true
    run: ./gradlew verifyPlugin

  - name: Classify failure
    if: steps.detect.outputs.needs_bump == 'true' && steps.verify.outcome == 'failure'
    run: |
      # 报告结构(本地实测 1.411):build/reports/pluginVerifier/<IDE>/plugins/<插件>/<版本>/verification-verdict.txt
      # 内容形如 "Compatible. 4 usages of deprecated API. ..."
      # 无任何 verdict 文件 = 下载/网络/配置失败,不能当兼容性问题处理
      VERDICTS=$(ls build/reports/pluginVerifier/*/plugins/*/*/verification-verdict.txt 2>/dev/null || true)
      if [ -z "$VERDICTS" ]; then
        echo "::error::verifyPlugin 失败且无 verification-verdict.txt,按基础设施失败处理(网络/下载/配置)"
        exit 1
      fi
      # 只要有任一端非 Compatible,就是真实二进制不兼容
      if grep -L '^Compatible' $VERDICTS | grep -q .; then
        echo "REAL_INCOMPATIBILITY=true" >> $GITHUB_ENV
      else
        echo "::error::Verifier 报告均标 Compatible 但任务失败,属构建/环境异常"
        exit 1
      fi
```

缓存由 `gradle/actions/setup-gradle@v6` 统一管理 Gradle 与 IntelliJ 平台依赖。不要再叠 `actions/cache` 缓存同一路径，避免双重保存与 restore/save 竞争。Verifier 首次仍会下载约 2.2 GB，之后由 setup-gradle 缓存复用。

- [ ] **Step 5: 通过则开 PR**

```yaml
  - name: Create compatibility PR
    if: steps.verify.outcome == 'success'
    env:
      NEW_VERSION: ${{ steps.detect.outputs.version }}
      GH_TOKEN: ${{ github.token }}
    run: |
      git config user.name "github-actions[bot]"
      git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
      BRANCH="chore/idea-compat-${NEW_VERSION}"
      git checkout -b "$BRANCH"
      git add gradle.properties
      git commit -m "chore: 支持 IntelliJ IDEA ${NEW_VERSION}"
      git push origin "$BRANCH"
      gh pr create --base main --head "$BRANCH" \
        --title "chore: 支持 IntelliJ IDEA ${NEW_VERSION}" \
        --body "$(cat <<'EOF'
      Plugin Verifier 已对最低支持版与新版本双端验证通过。

      发版前请确认：
      - [ ] review `gradle.properties` 的 untilBuild / verifierIdeVersions
      - [ ] 更新 README「前置要求」的 IDE 版本范围
      - [ ] 在 CHANGELOG.md 顶部补写发版版本段（发版流水线硬依赖）
      - [ ] 合并后按「发版流程」打 tag
      EOF
      )"
```

- [ ] **Step 6: 不兼容则开 Issue（先查重）**

```yaml
  - name: Create incompatibility issue
    if: env.REAL_INCOMPATIBILITY == 'true'
    env:
      NEW_VERSION: ${{ steps.detect.outputs.version }}
      GH_TOKEN: ${{ github.token }}
    run: |
      TITLE="IDEA ${NEW_VERSION} 二进制不兼容"
      if gh issue list --state open --search "$TITLE in:title" --json number --jq 'length' | grep -qv '^0$'; then
        echo "已有同类 issue,跳过"
        exit 0
      fi
      gh issue create --title "$TITLE" \
        --body "Plugin Verifier 判定当前插件在 IDEA ${NEW_VERSION} 上二进制不兼容。

      报告见本次 workflow 运行产物(\`build/reports/pluginVerifier/\`)。
      处理方向：核对失效的实验性 Terminal API / MCP 反射入口，修复后重跑 \`./gradlew verifyPlugin\`。"
```

- [ ] **Step 7: 上传 Verifier 报告（无论成败都要留证）**

```yaml
  - uses: actions/upload-artifact@v4
    if: steps.detect.outputs.needs_bump == 'true'
    with:
      name: plugin-verifier-report
      path: build/reports/pluginVerifier/
```

**注意：** `GITHUB_TOKEN` 创建的 PR 不会触发其他 workflow（GitHub 防递归限制）。本方案不依赖 PR CI，若将来想要，需改用 PAT 或 GitHub App。

### 验收标准

- [ ] `gradle.properties` 是兼容范围唯一真相源；`git grep -n 'untilBuild = "'` / `git grep -n 'since-build="'` 在代码与工作流中无第二处字面量
- [ ] 周检工作流手动触发一次：无新版本 → 正常结束；模拟旧上限 → 自动开 PR；模拟不兼容 → 自动开 Issue 且查重
- [ ] 自动 PR 内容只含 `gradle.properties` 一处改动，Verifier 报告中两端均 `Compatible`
- [ ] 现有 `release.yml` 行为不变：tag 触发、`verifyPlugin` 关卡、描述与 idea-version 从产物提取

### 风险与已知限制

- **Verifier 下载量**：单次约 2.2 GB，首次缓存冷启动约 10 分钟；缓存 key 变化（IDE 版本升级）会重新下载。
- **JetBrains API 变更**：`data.services.jetbrains.com` 字段若调整，检测步骤会失败（fail fast，不会静默跳过），需人工修工作流。
- **实验 API 仍会变**：自动 PR 只解决"发现与验证"，若 Verifier 报不兼容，仍要人工迁移 API——这是保留上限策略的固有成本。
- **不覆盖功能性冒烟**：焦点接力、终端生命周期、MCP 反射连通性 Verifier 查不了，PR 合并后仍需在真实 IDE 里点一次 Pi 图标确认。
