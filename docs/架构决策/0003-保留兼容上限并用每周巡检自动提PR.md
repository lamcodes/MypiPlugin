# 0003：保留兼容上限并用每周巡检自动提 PR

> 核对：2026-11-20 0.2.3

- **状态**：已采纳
- **关联文档**：[开发与发布指南.md](../开发与发布指南.md)、[架构说明.md](../架构说明.md)

## 背景

`0.2.2` 发布时因 `untilBuild = "262.*"` 停留在 2026.2，导致 IDEA 2026.3（build `263`）拒绝加载插件。若为省事直接删除 `untilBuild`（放开无限前向兼容），则由于插件重度依赖 Reworked Terminal 的 `@ApiStatus.Experimental` API，未来 IDE 改动签名时会从「装不上」退化为「装上后点 Pi 直接抛出 `NoSuchMethodError`」，故障更隐蔽、更难排查。

同时，每次 push 都跑 `verifyPlugin` 需要下载约 2.2 GB IDE 二进制，不适合常规提交 CI；而依赖 `pluginVerification.ides.recommended()` 会拉取未发布 EAP 导致解析不稳定。

## 决策

1. **保留 `pluginUntilBuild` 上限**：不放开无限前向兼容，且编译目标 `platformVersion` 固定在最低支持版本（当前 `2026.2`），避免开发期误用更新版本 API。
2. **兼容范围单一真相源**：将 `pluginVersion`、`platformVersion`、`pluginSinceBuild`、`pluginUntilBuild`、`verifierIdeVersions` 全部收敛到 `gradle.properties`，由 `build.gradle.kts`、`verifyPlugin`、`release.yml` 与 `compat-watch.yml` 共同读取。
3. **双端 Verifier + 每周自动巡检提案（不自动发版）**：
   - 发版流水线 `release.yml` 强制执行 `./gradlew verifyPlugin`（同时校验最低支持版与最新支持版）。
   - 独立定时工作流 `compat-watch.yml` 每周一自动查询 JetBrains 最新正式版，有新大版本则自动前移 `gradle.properties` 上限并跑双端 `verifyPlugin`：通过则幂等创建/更新 PR，确认真不兼容（基于 `verification-verdict.txt` 区分环境故障）则自动提 Issue。
   - 合并 PR、补 `CHANGELOG.md`、更新 README 与打 tag 发版保持人工确认。

## 取舍与后果

- **收益**：在保证实验 API 安全边界的前提下，将新版本适配从「被动等用户报障」转为「自动发现 + 验证 + 提案」，人工成本压缩到 review + 打 tag。
- **代价与约束**：
  - 使用默认 `GITHUB_TOKEN` 创建的自动 PR 不会触发其它 PR workflow（当前验证已在 `compat-watch.yml` 内完成，可接受）。
  - Plugin Verifier 仅覆盖二进制签名兼容，焦点接力、终端生命周期与 MCP 反射连通性仍需在真实 IDE 手工确认一次。
