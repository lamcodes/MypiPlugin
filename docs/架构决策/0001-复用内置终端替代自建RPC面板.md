# 0001：复用内置终端替代自建 RPC 面板

> 核对：2026-11-20 0.2.3

- **状态**：已采纳
- **关联文档**：[架构说明.md](../架构说明.md)、[领域词汇表.md](../领域词汇表.md)

## 背景

在 IntelliJ IDEA 中集成 Pi coding agent 存在两种路线：

1. **自建工具窗 + RPC/子进程协议**：插件启动 Pi 子进程并通过标准输入输出或自定义 RPC 协议通信，在侧边栏自建对话列表、Markdown 渲染与代码 Diff UI。
2. **复用 IDE 内置 Reworked Terminal**：插件在 IDEA 内置 Terminal 工具窗中启动 `pi` 交互式终端，插件仅负责生命周期触发与编辑器选区定位串注入。

## 决策

采用**方案 2（复用 IDE 内置 Reworked Terminal）**，并确立三项核心交互约束：

1. **单会话模型**：每个 `Project` 仅维护一个标题为 `Pi` 的终端 Tab；点击右侧 `Pi` 图标通过 `ToolWindowManagerListener.toolWindowShown` 每次触发（已开则聚焦，关闭后自动重启）。
2. **只发定位、只填不发送**：快捷键选用 `Ctrl+Alt+;`（避开中文输入法与 `Ctrl+Alt+P` / `Ctrl+Shift+*` 冲突），仅注入 `@path:行号` 或 `@path#L行号` 定位串，不粘贴代码正文，也不自动回车。
3. **焦点接力**：注入成功后激活 `Terminal` 工具窗并将键盘焦点交给 `TerminalView.preferredFocusableComponent`，让用户直接补问题回车。

## 取舍与后果

- **收益**：零 RPC 协议耦合、天然继承 Pi 全部原生 TUI 能力（流式输出、交互确认、快捷键、多轮上下文），插件体量极小、维护成本低。
- **代价与约束**：
  - 依赖 IDEA 2026.2+ 才稳定的 Reworked Terminal `@ApiStatus.Experimental` API（`TerminalToolWindowTabsManager`、`TerminalView.createSendTextBuilder` 等），最低版本被锁定在 `262`，所有调用必须用 `runCatching` 降级保护。
  - 不收集 Pi 回复做侧栏二次展示，也不支持多会话并行（若未来需要多会话，需重新评估 Tab 路由与选区目标选择交互）。
