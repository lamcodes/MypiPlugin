# 开发与发布指南

> 核对：2026-11-20 0.2.3

本文档是 MypiPlugin 开发构建、测试分层、发版与版本兼容巡检的权威操作说明。环境踩坑细节见 [tasks/lessons.md](../tasks/lessons.md)，版本策略决策见 [ADR-0003](架构决策/0003-保留兼容上限并用每周巡检自动提PR.md)。

## 开发环境要求

- **JDK**：21（`build.gradle.kts` 使用 `jvmToolchain(21)`；产出字节码在 IDEA 2026.2/2026.3 的 JBR 25 上向下兼容）
- **Gradle**：使用项目自带 Wrapper（`./gradlew` / `.\gradlew.bat`），无需本地预装
- **Kotlin / 插件工具链**：Kotlin `2.4.0` + IntelliJ Platform Gradle Plugin `2.18.1`（IDEA 2026.2 平台类为 Kotlin 2.4.0 metadata，不可降级 Kotlin 编译器）

> **注意**：`buildSearchableOptions` 任务在中文 Locale 下会报错，已在 `build.gradle.kts` 中默认禁用；`gradlew` 在 Git 中必须保持 `100755` 可执行位（Windows 改动后若降权可用 `git update-index --chmod=+x gradlew` 恢复）。

## 常用构建与验证命令

```bash
# 仅编译主代码与测试代码（最快验证入口）
./gradlew compileKotlin compileTestKotlin

# 运行全部 Tier1 纯逻辑单测（零 IntelliJ 依赖，秒级）
./gradlew test \
  --tests "com.mypi.plugin.SelectionContextBuilderTest" \
  --tests "com.mypi.plugin.PiSettingsStateTest" \
  --tests "com.mypi.plugin.PiMcpConfigStoreTest" \
  --tests "com.mypi.plugin.PiExecutableResolverTest"

# 打包插件 zip（产物在 build/distributions/）
./gradlew buildPlugin

# 对 gradle.properties 中声明的最低/最新 IDE 版本执行双端二进制兼容检查
./gradlew verifyPlugin

# 启动沙盒 IDE 手工冒烟测试
./gradlew runIde
```

## 测试分层与 CLI 约束

| 层级 | 测试类 | 运行方式 | 说明 |
|---|---|---|---|
| **Tier1（纯逻辑，JUnit 5）** | `SelectionContextBuilderTest`、`PiSettingsStateTest`、`PiMcpConfigStoreTest`、`PiExecutableResolverTest` | CLI 直接通过 `--tests` 执行 | 零 IntelliJ 平台依赖，覆盖定位串/换行边界、配置状态、MCP JSON 存储/去重、可执行路径解析 |
| **Tier2（平台集成，`BasePlatformTestCase`）** | `SendSelectionActionTest`、`PiConfigurableTest`、`PiSettingsPlatformTest` | 仅在真实 IDE 内通过运行配置或手工冒烟执行 | **禁止在 CLI 跑全量 `./gradlew test` 或直接跑 Tier2**：当前 IDEA 2026.2 sandbox 存在协程 debug metadata 版本冲突，会长时间卡死（详见 [tasks/lessons.md](../tasks/lessons.md)） |

## 单一真相源（SSOT）治理

发版与兼容维护涉及的所有元信息仅保留一处权威定义，禁止跨文件复制：

| 事实 | 权威位置 | 消费方 |
|---|---|---|
| 插件版本、编译目标版本、`sinceBuild` / `untilBuild`、Verifier 双端目标 | [gradle.properties](../gradle.properties) | `build.gradle.kts`、`verifyPlugin`、`release.yml`、`compat-watch.yml` |
| 插件展示描述 | [src/main/resources/META-INF/plugin.xml](../src/main/resources/META-INF/plugin.xml) | 插件包、`release.yml` 生成 `updatePlugins.xml` |
| 版本更新说明 | [CHANGELOG.md](../CHANGELOG.md) | `release.yml` 提取对应 `## [x.x.x]` 段作为 Release body（缺失即失败） |

## 发版流程

触发入口为 [release.yml](../.github/workflows/release.yml)（监听 `v*` tag push）：

1. 更新 [gradle.properties](../gradle.properties) 中的 `pluginVersion`。
2. 在 [CHANGELOG.md](../CHANGELOG.md) 顶部新增 `## [x.x.x] - YYYY-MM-DD` 段落。
3. 若兼容版本范围变化，同步更新根目录 [README.md](../README.md) 的「前置要求」。
4. 提交并推送 tag：
   ```bash
   git commit -am "release: x.x.x"
   git tag vx.x.x
   git push origin main --tags
   ```
5. CI 自动完成：`buildPlugin` → `verifyPlugin`（双端兼容门禁）→ 提取描述与兼容范围生成 `updatePlugins.xml` → 读取 `CHANGELOG.md` 发布 GitHub Release。

## 每周 IDEA 兼容巡检

由 [compat-watch.yml](../.github/workflows/compat-watch.yml) 在每周一北京时间 10:00（UTC `0 2 * * 1`）自动运行，也支持手动 `workflow_dispatch`（可通过 `override_latest` 提前演练新版本）：

1. 查询 JetBrains 官方 Releases API 获取最新正式版 IDEA 与构建号。
2. 若大版本号大于当前 `pluginUntilBuild`，自动前移 `gradle.properties` 中的 `pluginUntilBuild` 与 `verifierIdeVersions`（保持「最低支持版 + 最新版」双端）。
3. 运行 `./gradlew verifyPlugin`：
   - **通过**：幂等推送分支 `chore/idea-compat-<版本>` 并创建（或更新）升级 PR；人工 review、更新 README/CHANGELOG、合并并打 tag 发版。
   - **失败**：解析 `verification-verdict.txt` 区分「真不兼容」与「网络/下载等基础设施故障」；仅确认真不兼容时自动查重并创建 Issue，附带 `plugin-verifier-report` 产物。
